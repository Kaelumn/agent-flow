⟶Agent Flow

让 agent 按流程图办事，一步不漏

Agent Flow 把 MSP 的 SOP 存成流程图。agent 在聊天里和你一起把流程建出来，你在画布上看得见、改得了；执行时服务端逐步把关，agent 只能按图走。

面向 MSPbots 平台通过 MCP 接入任意 agent手册版本 2026-10

痛点为什么写在 skill 里的 SOP 不可靠

常见做法是把 SOP 写进 skill：一段说明加一张 Mermaid 流程图，再挂上工具，交给 agent 执行。流程少、步骤短的时候还行。一旦流程变多、分支变复杂，问题就集中出现：

漏步、乱序

agent 读的是一段文字，执行到第 7 步时忘了第 4 步还没做，或者先建账号再查重。

服务端按图把关

每一步由服务端告诉 agent 该调哪个工具、能走哪几条线；乱序提交和不存在的连线会被直接拒绝。

参数填错

工单号、上一步返回的用户 ID，agent 靠“理解”去拼，经常拿错字段或自己编一个。

引用写法 + 运行时填值

参数写成 {{input.ticket_id}}、{{new_user.id}}。建图时校验来源是否存在、是否一定先执行；运行时由服务端填好真实值。

异常不会处理

工具报错后 agent 要么停住，要么假装成功继续往下走。

每一步写明失败怎么办

停止、继续，或跳到通知人的步骤。结果必须如实上报成功、失败或跳过（跳过要写原因）。

几百套流程没法管

流程藏在一堆 skill 文件里，没人看得懂全貌，改一处不知道会影响哪里，也没有版本。

可视化 + 校验 + 版本

每个流程都是一张可以搜索、浏览的图；发布前必须通过校验；每次发布生成不可变版本，可以随时回到旧版。

agent 改了什么看不见

让 agent 修改流程，只能读它的回复，无法逐处检查。

实时播放 + 修改历史

agent 每改一处，画布就把它逐步画出来；每次修改都记在历史里，谁在第几版改了什么一清二楚。

工作方式四个角色，一张图

Agent Flow 不是一个新的 agent，也不是工作流引擎。它是你现有 agent 旁边的“流程本”：agent 通过 MCP 读写流程图、按图执行；人通过画布查看和修改同一张图。

MSPbots 对话人提出需求、收到汇报，标注也送到这里
你的 agent理解需求，建图、改图，按图调用工具
Agent Flow存流程、做校验、管版本，执行时逐步把关
画布嵌在对话旁边，实时显示并可直接修改

工具（Autotask、Microsoft 365、Teams 等）仍由 agent 自己调用；Agent Flow 只决定“下一步做什么、能走哪条线”，并记录每一步的结果。

核心概念读懂一张流程图

概念说明
流程（Flow）一套 SOP。有一份可编辑的草稿和若干已发布的版本。描述里写用途、适用范围和固定参数（比如各办公室对应的邮件组）。
开始节点每个流程一个，声明运行时要传入的参数，例如 ticket_id。
步骤一次工具调用。包含：调用哪个工具、每个参数从哪来、给 agent 的指引、结果存成什么名字（输出键），以及失败时怎么办。
结束节点业务结果：completed 完成、stopped 无需处理、failed 失败。
连线与分支一个步骤有多条出线时，每条写一句自然语言条件，由 agent 根据刚拿到的数据判断；最多一条标为默认（Otherwise）。
引用{{input.名称}} 取运行参数，{{输出键.字段}} 取前面步骤的结果。校验器检查来源存在且一定先执行，运行时自动填值。
运行（Run）基于某个已发布版本的一次执行，记录走到哪一步、每一步的参数和结果。
标注审阅人在画布上画框圈出问题、写一句说明，发回对话。不保存，发完即走。

功能一览它能做什么

聊天建图

agent 通过 MCP 增删改节点和连线，查询真实可用的工具，不会编造工具名。配套 flow-designer skill，教 agent 怎么访谈、怎么建、怎么自查。

实时画布

agent 的每次修改都按流程顺序逐个播放：节点弹出、连线画出、改动闪烁、删除淡出，镜头自动跟随。

手动编辑

拖线连接、拖到空白处新建步骤、在连线上插入步骤、可搜索的工具选择器、带引用补全的参数编辑、一键整理布局。

建图时校验

走不通的分支、到不了的步骤、未知工具和参数、引用来源缺失或可能未执行，都会标在节点上；有错误不能发布。

画框标注

圈出要改的地方写一句话，发送后作为系统通知进入 MSPbots 对话，带上步骤、连线和修订号，agent 拿到就能改。

版本与历史

发布生成不可变版本，运行永远使用最新发布版。修改历史记录每次变更的人、来源（画布或 agent）和内容，可恢复旧版本到草稿。

按图执行

flow-runner skill 驱动 agent 逐步执行：服务端给出当前步骤、已填好的参数和可选出线，拒绝乱序；画布可回放每次运行的轨迹。

实时工具目录

直接从你配置的 MCP 服务读取工具及参数结构，按工具的只读标记区分“读”和“写”。

使用 · 1用聊天建一个流程

在 MSPbots 里像对同事一样描述流程即可。agent 会先确认可用工具，然后按执行顺序一步步建，右边的画布同步长出来。

帮我建一个密码重置的 SOP：根据 Autotask 工单找到用户；M365 里没有这个账号就在工单里备注后结束；有的话重置密码，用 Teams 把临时密码发给他的经理，最后在工单里备注。
好的。我先确认一下能用的工具……找到了 graph_reset_password、autotask_create_ticket_note 等。流程的输入是工单号 ticket_id。
第 1 步：读取工单，找出要重置密码的用户。
账号不存在的分支：在工单里备注，然后结束。
流程建好了：7 个步骤、2 个分支，校验 0 个错误。你可以在右边画布上检查，觉得哪里不对就画框标注发给我；没问题的话我就发布。

说清楚这几件事，流程才可靠

  1. 触发和输入

    什么情况下启动（工单创建、表单、定时），运行时带什么参数；哪些请求应该直接忽略。

  2. 完成的标准和禁区

    什么算办完；什么绝对不能做，比如“不要关闭原工单”。

  3. 每个分叉点

    哪里会分开走，依据是什么数据。

  4. 固定参数

    对照表和常量的真实值：办公室对应哪些组、用哪种 license、通知谁。

  5. 失败时怎么办

    每个会改动数据的步骤失败后，是停止、继续，还是通知人。

没时间回答问题？ 直接让 agent 自己建。它会对没说清的地方做最保守的假设，写进流程说明的“待确认问题”，最后统一列给你。

使用 · 2在画布上查看和修改

流程图铺满画布。左上角是标题栏（流程名、状态、问题数、发布）；右上角一列图标打开面板：属性、问题、历史、运行记录。面板默认收起，选中节点时自动弹出。

操作方法
移动画布滚轮上下滚动，Shift + 滚轮左右滚动；按住 Space 或鼠标中键拖动
缩放Ctrl + 滚轮，或触控板双指捏合；工具栏的百分比按钮适应屏幕
连接两个步骤悬停节点，从底部圆点拖到另一个节点
接着加一步从节点底部圆点拖到空白处松开
在中间插入一步选中连线，点中间的 +；或在连线面板点 Insert step
编辑步骤点击节点，在属性面板里选工具、填参数（输入 {{ 弹出可用引用）、设置失败处理
整理布局工具栏 Tidy
删除选中后按 Delete，删除步骤前会确认
收起面板Esc，或点击空白画布
开始标注A，或工具栏 Annotate

你在画布上的修改和 agent 的修改走同一条写入路径：同样的校验、同样的修改历史。两边同时改时，后提交的一方会收到“流程已变化”的提示并拿到最新内容，不会互相覆盖。

使用 · 3标注问题，发回 agent

  1. 进入标注模式

    按 A。画布冻结，鼠标变成十字。

  2. 圈出问题

    拖一个框，或直接点击某个步骤，写一句要改什么，回车确认。可以连续画多个框，滚动画布去标别处。

  3. 发送

    点 Send。标注作为系统通知进入当前对话，画框清空。单独打开画布时按钮是 Copy，复制后粘贴到对话里。

[Agent Flow] 1 annotation on "Password reset (demo)" (flow g_muqjpq6jtippmejlog, draft revision 17) 1. 经理不在时改发给 IT 组 On: step "Send the password to the manager" (tell_manager) Read the flow with flow_get, apply the changes to the draft, then summarise what you changed for each annotation.

框住的不是像素位置，而是具体的步骤和连线。框在空白处会记为“附近的连线”，框住大半张图则视为针对整个流程。修订号让 agent 知道你标注时看到的是哪一版。

使用 · 4发布与运行

草稿通过校验后点 Publish，写一句这一版改了什么。运行永远使用最新发布的版本，草稿可以继续改，不影响正在跑的流程。

agent 怎么按图执行

  1. run_start

    传入流程和参数，拿到第一步：要调的工具、已填好的参数（resolvedArgs）、指引和可选出线。

  2. agent 自己调用该工具

    用 MSPbots 里已有的工具连接，Agent Flow 不代为调用。

  3. run_submit

    上报结果（成功、失败或跳过）和选择的出线。服务端检查出线是否属于当前步骤，再给出下一步。

  4. 重复直到结束节点

    每一步都留在运行记录里，画布可以回放轨迹，失败的步骤标红。

状态含义
running进行中，停在某一步等待 agent 上报
completed / stopped / failed到达对应结果的结束节点
cancelled被手动取消

集成嵌入 MSPbots

画布以 iframe 嵌在对话右侧（约占屏幕 2/5），和单独打开时是同一套界面，会按宽度自动调整：宽度 720px 以上，面板从右侧浮出；更窄时，面板从底部弹出，工具栏只显示图标。

<iframe src="https://flows.example.com/#/flows/<流程 id>" allow="clipboard-write"></iframe>

标注通过浏览器消息送达：画布发出 agent-flow.annotations，MSPbots 校验来源、把其中的 text 作为系统通知插入对话并触发 agent，再回发 agent-flow.annotations.ack。3 秒内收不到回执，画布会改为复制到剪贴板并提示用户。完整格式见仓库 docs/integration/canvas-annotations.md。

本地可以用 http://localhost:4100/host?flow=<流程 id> 的模拟对话页试嵌入和标注。

运维部署与配置

前后端在同一个仓库：apps/server（Fastify + MCP）、apps/web（画布）、packages/core（模型和校验，前后端共用）。数据库默认 MySQL，可切换 PostgreSQL。

npm install
npm run db:migrate
npm run build
npm start -w @agent-flow/server   # 同时提供 /api、/mcp 和打包后的画布
环境变量说明
DATABASE_URL数据库连接串；DB_DIALECT 选 mysql 或 postgres
AUTH_TOKENStoken:工作区:身份，逗号分隔。画布和 agent 各用自己的 token
TOOL_SERVERS_CONFIG工具目录来源：MCP 服务列表（JSON）；也可用 TOOL_CATALOG_PATH 指向静态目录
PUBLIC_WEB_URL画布地址，agent 的回复里会附上画布链接
EMBED_ORIGINS允许嵌入画布并接收标注的页面来源，如 https://app.mspbots.ai

给 agent 接上 Agent Flow

在 agent 的 MCP 配置里加上 /mcp 地址和 agent 的 token，再装上两个 skill：flow-designer（建图、改图、处理标注）和 flow-runner（按图执行）。连接后服务端会把使用说明发给 agent。

FAQ常见问题

agent 建图时返回很多“未连接”的提示，正常吗？

正常。建图过程中，修改结果的 issues 只列现在就是错的问题（比如工具名不存在）；还没连上、引用的步骤还没加这类，只在 unfinished 里计数，建完自然消失。最后用 flow_validate 看完整结果。

分支条件里能写 {{引用}} 吗？

不能。条件用自然语言描述刚拿到的数据，例如“账号不存在”；条件里的引用既不校验也不填值。

标注会保存吗？发错了怎么办？

不保存。发出去就是对话里的一条通知，在对话里告诉 agent 忽略即可。发送前可以点框上的编号修改或删除。

我和 agent 同时改同一个流程会怎样？

画布的每次写入都带修订号，agent 按 skill 也会带上。后提交的一方会收到冲突提示并拿到最新内容，需要重做那一步修改，不会互相覆盖。

运行中途 agent 断开了怎么办？

运行状态在服务端，重新连接后用 run_current 取回当前步骤继续。接管、超时、重试和人工审批节点在下期规划中。

现在还有哪些限制？

身份暂用配置文件里的 token，正式接入 MSPbots 账号体系后会替换；嵌入画布目前仍需手动输入 token。多实例部署需要把实时推送换成 Redis。PostgreSQL 已支持，尚未在生产规模下实测。
